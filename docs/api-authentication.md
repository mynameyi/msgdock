# API Key 与系统鉴权

MsgDock 使用实例级 API Key，不需要创建接入应用、clientId/clientSecret 或交换 Token。控制台的“API Key”页面直接创建密钥，仅填写用途名称；创建后可以在列表中随时查看和复制完整值。所有有效 Key 都可发送和查询本实例的通知，不授予管理员权限。

## 调用方式

系统默认开启鉴权。请求使用统一路径：

```http
POST /api/v1/notifications
Authorization: Bearer <API_KEY>
Content-Type: application/json

{ "target": { "type": "targets", "ids": ["ch_a7c92e4f6b18"] }, "message": { "text": "你好，MsgDock" } }
```

在“系统设置 → 通知 API 鉴权”关闭开关后，请求可以完全省略 Authorization，无需申请 Key。通知查询也跟随此开关；后台仍需管理员登录。请求若主动携带无效、停用或已撤销 Key，始终返回 401，不降级为匿名。

Key 保留 SHA-256 摘要用于鉴权，并使用实例主密钥保存 AES-256-GCM 加密副本。管理员登录后，列表直接显示完整 Key 并支持复制；摘要和密文本身不返回给页面。轮换时创建新 Key，更新调用方后撤销旧 Key。停用可恢复；撤销不可恢复。队列执行时重新检查 Key 状态，尚未执行的关联投递会取消。原 Key 已失效的投递不能沿用旧记录重发，需使用有效 Key 创建新通知；管理员重发此类记录返回 409，不影响管理登录。

## 限流与幂等

系统设置中的每分钟发送上限由所有 Key 和匿名调用共用；平台插件另有渠道级限额。后台测试发送直接用管理员会话，无需选择 Key。

JSON 字段 idempotency_key 为可选项。不传时每次请求创建新通知；传入时在同一 Key 下去重，匿名调用共用匿名范围。相同键与不同内容返回 409。不同 Key 的幂等范围独立，轮换 Key 后应先核对未确认的通知，避免跨 Key 重试重复发送。

## 完整密钥的保存

迁移 202610210005_recoverable_api_keys 增加可空的密文字段。迁移不修改既有 Key，也不自动轮换旧凭证。新创建的 Key 可在刷新页面、重启容器后继续查看和复制。旧记录的 key 返回 null；需要可查看的 Key 时创建新 Key，更新调用方后再撤销旧 Key。主密钥继续使用 /data/secrets/master-key 或 MSGDOCK_MASTER_KEY，备份时与数据库一并保留。

## 旧版本迁移

迁移 202610210004_global_api_keys 移除 Application 表和旧应用路由。旧 Key 的 ID、摘要、前缀、撤销时间与创建时间保留，名称和启用状态从原应用迁移；旧密钥可继续使用新通知路径。旧 Key 仍然有效。旧记录只有单向摘要，无法还原完整值，列表会明确提示。

通知、投递、渠道、模板、会话和审计记录保留。历史通知优先关联原应用中最早的有效 Key；没有有效 Key 时选择最早 Key，无 Key 的记录保留为历史来源。原来同一应用多个 Key 共享的幂等范围调整为每个 Key 独立，历史通知保留原幂等键及摘要。

升级后系统鉴权统一默认开启，旧应用的免鉴权设置不沿用。需要免 Key 调用时在系统设置关闭开关。调用方将 /api/v1/apps/{appKey}/notifications 改为 /api/v1/notifications，查询路径同样去掉 apps/{appKey}。旧应用管理接口不再提供。

升级前备份数据库与加密主密钥。迁移修改数据库结构，回退时需恢复匹配的备份，不能仅替换为旧镜像。
