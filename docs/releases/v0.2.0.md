# MsgDock 0.2.0 渠道插件化

## 变更

在 0.1.0 MVP 上加入核心引擎、渠道插件和 SDK 的扩展边界，保持 React Feature-based、NestJS 业务模块及一个最终 Docker 镜像的部署方式。

- packages/plugin-sdk 提供版本化接口、Schema / UI 类型、发送结果与宿主 HTTP 契约；不依赖业务数据库或 NestJS。
- 企业微信群 Webhook、飞书群 Webhook、钉钉企业机器人迁入 plugins/ 下的三个独立包，各自声明配置、接收目标、消息能力、限额和官方网络主机。
- packages/channels 提供内置装配、注册中心、SDK 兼容校验、精确版本解析、Schema 校验和执行保护；测试 mock 只在测试模式注册。
- GET /api/admin/channel-plugins 提供公开插件目录。渠道类型列表、配置字段、目标字段和概览名称由目录驱动；渠道页面和投递详情展示版本。
- 渠道配置整体加密保存，管理读取不返回凭证。发送标记、幂等、队列、授权、限速执行、重试和审计继续由核心控制。
- 迁移为旧渠道和投递补齐插件版本；新任务与关联重发固定插件及配置版本，缺失版本明确失败，不自动改用其他插件。
- 内置插件编译进入同一镜像，API 与 Worker 使用同一个启动装配；升级重启后生效。

## 兼容性

已有 type、凭证密文、会话和 API Key 保留。新配置接口支持通用 credentials / targetConfig，服务端按已注册插件 Schema 校验；顶层 openConversationId 保留为 0.1.0 兼容别名。已有渠道不能直接切换插件版本，采用新建渠道、调整授权和路由、排空旧任务的方式升级。

## 验证范围

- 插件注册与 SDK 兼容、精确版本固定、配置 / 目标 Schema、官方地址约束、签名、平台错误、发送前标记、未知结果保护和适配器生命周期的单元验证。
- API 集成覆盖插件目录、未知插件 / 版本拒绝、必填目标 / 额外字段校验、版本快照，以及原有鉴权、幂等、模板和投递流程。
- 单镜像构建、0.1.0 测试卷升级、旧待投递任务恢复、重启、队列丢失恢复与浏览器动态表单验证。

本地 build、lint、typecheck、19 项单元测试、最终 Docker 镜像构建与上述集成验证通过。浏览器验证覆盖三个官方插件的字段切换、旧字段清除、创建与编辑时凭证保留，以及 320–1440px 的页面布局；未发现脚本异常。旧卷升级验证包含一条 0.1.0 待执行任务，迁移后仅产生一次实际发送。

模拟平台验证不替代真实企业环境联调；本轮不使用真实 IM 凭证或向真实群发送消息。

## 当前边界

本版只实现可信内置 HTTP 文本插件。外部离线包安装、在线插件市场、热替换、任意第三方代码隔离、智能机器人长连接、复杂嵌套 Schema 表单和配置自动迁移尚未实现。生命周期钩子已经接通，但不等于已交付长连接渠道。

其他 MVP 限制沿用 [0.1.0 版本说明](v0.1.0.md)，插件开发及升级约定见[渠道插件文档](../channel-plugins.md)。
